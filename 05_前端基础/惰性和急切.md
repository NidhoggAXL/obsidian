
在软件开发中，“惰性”（Lazy）和“急切”（Eager）是两种截然相反的执行策略，主要涉及**资源初始化**和**数据求值**的时机问题。

# 一、核心定义

-   **惰性 (Lazy)**
    -   **原则**：**“不到万不得已，绝不执行”**。
    -   将计算或资源的创建推迟到第一次被访问或使用时。
    -   就像**点外卖**：饿了才做，节省当前的启动时间，但第一次吃需要等待。

-   **急切 (Eager)**
    -   **原则**：**“未雨绸缪，提前做完”**。
    -   在程序启动或变量定义时立即完成所有计算和资源加载。
    -   就像**满汉全席**：一上桌就能立刻开吃，但如果吃不完就浪费了内存和性能。

# 二、核心对比（速查表）

| 维度        | 惰性 (Lazy)   | 急切 (Eager)      |
| :-------- | :---------- | :-------------- |
| 执行时机  | 调用/读取时（运行时） | 定义/启动时（编译或初始化时） |
| 启动速度  | 快（无需预热） | 慢（需加载全部资源）  |
| 内存占用  | 低（按需分配） | 高（预分配全部空间）  |
| 首次响应  | 较慢（首次加载耗时）  | 极快（数据已在缓存中） |
| 资源浪费  | 无（未被调用则不计算） | 存在（可能计算了用不到的数据） |
| 代码复杂度 | 较高（需处理状态判断） | 较低（逻辑线性、直观）     |


# 三、JavaScript 代码示例

## 3.1 属性初始化对比（资源加载）

```js
// ---------- 急切模式：构造时立即计算 ----------
class EagerReport {
  constructor(data) {
    this.data = data;
    // 不管用不用，先花1秒生成报告
    this.report = this.generateHeavyReport();
    console.log('急切：报告已生成');
  }
  generateHeavyReport() {
    console.log('执行昂贵计算...');
    return this.data.map(x => x * 100);
  }
}

// ---------- 惰性模式：调用时才计算 ----------
class LazyReport {
  constructor(data) {
    this.data = data;
    this._report = null; // 只占位，不计算
    console.log('惰性：报告未生成，占位完成');
  }
  generateHeavyReport() {
    console.log('执行昂贵计算...');
    return this.data.map(x => x * 100);
  }
  show() {
    // 关键点：只有在第一次调用时才会去计算，后续复用缓存
    if (this._report === null) {
      this._report = this.generateHeavyReport();
    }
    return this._report;
  }
}

// 使用对比
const eager = new EagerReport([1,2,3]); // 立即输出：执行昂贵计算...
const lazy = new LazyReport([1,2,3]);   // 输出：惰性：报告未生成（瞬间完成）
lazy.show(); // 此刻才输出：执行昂贵计算...
```

## 3.2 数据求值对比（处理无限数据）

```js
// 急切：filter 和 map 会立即遍历全部数据（生成100个数字再过滤）
const eagerResult = Array.from({ length: 100 }, (_, i) => i + 1)
  .filter(n => n % 2 === 0)
  .slice(0, 5); 
console.log('急切结果：', eagerResult); // [2, 4, 6, 8, 10]

// 惰性：Generator 函数每次只计算到下一个所需值即停止（不生成大数组）
function* lazyEvens() {
  let num = 1;
  while (true) { // 无限循环，但因惰性不会卡死
    if (num % 2 === 0) yield num;
    num++;
  }
}
const gen = lazyEvens();
const lazyResult = [gen.next().value, gen.next().value, gen.next().value, gen.next().value, gen.next().value];
console.log('惰性结果：', lazyResult); // [2, 4, 6, 8, 10]
// 注意：惰性模式只循环到数字10就停了，而急切模式创建了100个数字的数组。
```

# 四、优缺点分析

- **惰性的优点**：应用启动极快；节省系统资源（CPU / 内存）；程序运行更高效（避免计算死代码）。
    
- **惰性的缺点**：首次调用时可能造成明显的界面卡顿（Frozen UI）；多线程环境下需处理并发安全问题；代码可读性稍差。
    
- **急切的优点**：主要逻辑预先完成，交互响应延迟低；确定性高，易于调试；代码结构简单直白。
    
- **急切的缺点**：启动时如果加载过多无用资源，会导致启动缓慢；提前分配内存可能导致内存泄漏或溢出。

# 五、适用场景指南

| 场景类型                | 推荐策略   | 理由                        |
| ------------------- | ------ | ------------------------- |
| **大型配置文件 / 环境变量**   | **惰性** | 程序可能不需要全部配置，按需加载更快。       |
| **数据库连接池**          | **惰性** | 连接成本高，不用则不建，避免占用数据库资源。    |
| **单例（Singleton）实例** | **惰性** | 经典的单例模式实现方式，确保全局只用一次。     |
| **UI 界面渲染**         | **惰性** | 如长列表虚拟滚动、图片懒加载，只渲染可视区域。   |
| **必须的全局日志模块**       | **急切** | 日志需要随时可用，初始化简单且必须启用。      |
| **核心业务计算缓存**        | **急切** | 数据必须存在且高频读取，提前算好放入缓存提升性能。 |
| **小型工具库（如 Lodash）** | **急切** | 功能独立，初始化成本极低，急切调用更便捷。     |

# 六、总结

**惰性** 本质上是 **“用时间换空间”**（用首次执行的时间，换取平时极低的内存占用和更快的启动速度）。

**急切** 本质上是 **“用空间换时间”**（用预先占据的内存和启动等待时间，换取极致的运行时响应速度）。
